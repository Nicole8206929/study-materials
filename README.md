## 上传并自动分类

书架的“上传书籍（仅本人）”打开 `upload.html`。先勾选一个或多个分类、填写标签，以及选择“每个文件分别入库”或“合订一本 PDF”，再前往 GitHub 私有上传页。同一份资料会同时显示在所有勾选的类别中，只建立一条书目。分类信息已写进该批次的说明；添加文件后等待所有附件成功，点击 **Publish release**，然后回上传页看处理结果。私有仓库的 Release 发布仍然私有，不会公开原件，也不需要 Save draft。

首次配置由助手代办，用户只在 GitHub 官方设备授权页确认一次 GitHub CLI 授权。助手配置仅限公开书架的可写部署密钥，将私钥密封到私有仓库 `PUBLIC_SHELF_SSH_KEY`，再运行启用检查；不把用户的 OAuth 令牌当作长期发布密钥。工作流仍兼容既有 `PUBLIC_SHELF_TOKEN`。说明在 `upload-setup.html`。未验证配置时 `upload-automation.json` 保持 `ready:false`，按钮禁用，不宣称自动入库已生效。本网站不接收令牌；不要把 GitHub 凭据放进 URL、聊天或公开仓库。

私有仓库的 GitHub Actions 在新批次发布后处理 PDF、EPUB、PPT 和 PPTX。PDF/EPUB 可分别入库；课件使用已有工具生成静态 PDF，含隐藏页和备注；PDF/课件可按文件名自然顺序使用 LaTeX 合订，不改写原文、不保留音视频。只把书目、最多 10 页 WebP 试读和不含原件地址的状态写入公开仓库。原件及自动处理的结果保留在私有 Release 中，不自动删除未来批次的原件。旧的 97 份物理批次继续使用其独立完成记录和既有清理规则。

上传页区分待发布、云端处理中、网站发布中、已入库与失败。GitHub 任务实查线上全部所选分类、小分类、标签和试读图片后才写 `ready`；前端把确认成功的批次从待处理列表移到最近成功记录，并提供每个所选分类的入口。重复内容不增加重复书目，保留已有分类、小分类和标签，再补上本次新选项。失败保留原件，用户可进入私有任务页点 Re-run all jobs；已发布书目而私有记录提交中断时，重试根据不可变的附件 ID 恢复，不凭同名文件猜测。

打开 GitHub 创建页只会记下一条“未完成”记录，不代表文件已上传。尚无公开处理回执时，提示先完成附件上传和发布，并提供返回 GitHub 草稿列表的入口。刷新只查询结果，不重传手机文件；短暂查询错误与处理阶段分别保存，后续查询恢复时会清除临时错误，不误报为入库失败。

云端转换开始后可关闭手机，不需运行常驻服务器、扩展或书签。文件尚在手机向 GitHub 传输时，手机系统仍可能暂停浏览器。页面提供 OPPO/vivo 的后台活动、后台联网和最近任务锁定说明；这些设置不能保证黑屏传输，也不是断点续传。

### 补齐旧批次

原“手机本地核对并生成仅缺失文件补传包”仍在折叠区，携带 batch 的旧私人链接会自动展开。可累计选择最多 1000 份 PDF/PPT/PPTX、逐项移除、撤销移除和按文件夹追加；浏览器的单次选择限制仍由手机控制。手机按 SHA256 和准确大小去重，只将缺失原件打成 ZIP，不上传文件字节。旧批次目前已完成并转为只读私有归档。这个 ZIP 是本地核对产物，不是新自动入库的上传格式；新资料使用上方分类上传入口。

旧核对记录是 AES-GCM 加密快照，解密信息只在私人链接片段和本机已保存上下文。已合订记录明确显示历史归档，不把已清理原件说成仍在线。页面使用 256 KiB 分块读取和 Blob 文件片段，不把整个文件读入单个 ArrayBuffer。缺少记录不能当作零上传；读取失败可重试，主动取消保持取消。

核对/打包期间请求 Screen Wake Lock，后台释放、返回前台重试并刷新记录；离线时保留选择和结果，重新联网后重试。系统杀死网页后需重选文件，已上传附件不丢失。该工具不接管 GitHub 原生上传，不保证手机黑屏传输。旧书签/扩展源码仅保留审查，不作为当前上传方案。OPPO/vivo 真机尚未验证，不把 Chromium/Firefox 的模拟验收说成真机结果。

构建 `npm run build:checker` 后提交生成的 `assets/upload-checker.js`。`npm test` 检查新分类交接、失败与成功状态、重试、手机布局和原核对/打包流程。浏览器验收中的 GitHub 上传交接使用测试替身，不将其称为已实际登录手机并上传。

## 本地运行和检查

```bash
python3 -m http.server 8000
python3 scripts/check_public_shelf.py
npm ci
npx playwright install chromium firefox
npm test
```

只提交试读图片和公开书目信息，不要将原件、压缩包、令牌或环境文件放回公开仓库。CI会检查原件扩展名、目录中的下载路径及试读数量。

生成试读时使用私有原件仓库中的 `scripts/build_public_shelf.py`，在独立目录生成新的公开发布内容，再运行上述检查。不要将私有仓库的历史推送到此仓库。

书籍权利归原作者或出版方所有，根目录MIT许可仅覆盖自有代码，不代表第三方书籍授权。

分类列表由 `books.json` 的 `categories` 字段维护。空分类也会显示，选择后显示“暂未添加书籍”；其筛选网址可分享并在刷新后保留。新增书籍时使用对应分类 ID，无须再修改页面代码。

大学数学包含分析、代数、几何与拓扑、概率与统计、应用数学五个小分类，定义在 `subcategories`。上传时勾选大学数学后，可继续勾选多个小分类；小分类为选填。书目使用 `cats`、`subcats` 保存全部归属，同时保留 `cat`、`subcat` 作为第一项，兼容旧书目。各分类的数量和筛选按归属计算，全部资料始终按唯一书目计数。网址 `cat=university-math&subcat=analysis` 可保存筛选。
