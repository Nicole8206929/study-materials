这是本人的管理入口。上传时使用自己的 GitHub 账号；访客浏览书架和试读不需要登录。

请先在 Firefox（火狐浏览器）里打开本页。在聊天窗口或其他浏览器里点安装，不会自动装到 Firefox。先点下面的复制按钮，再打开手机桌面的 Firefox，把地址粘贴到地址栏。

首次安装，只需一次

  1. 在安卓手机安装 Firefox 浏览器。请在 Firefox 中打开本页，其他浏览器不会自动启用此助手。
  2. 在 Firefox 中点击 安装 Tampermonkey 扩展，点“添加到 Firefox”并确认。如果需要查找扩展菜单，点 Firefox 右上角或右下角的 ⋮ → 扩展（附加组件）。
  3. 点击下面的“安装上传助手”，在扩展弹出的安装页确认安装。若只看到代码，先确认 Tampermonkey 已启用，再重新打开安装链接。

点安装后只有代码，没有弹出安装页？

先确认正在用 Firefox，且 Tampermonkey 已启用。可以试试 Tampermonkey 官方备用安装入口。

仍然不行时，不需要复制代码：点 Firefox 的 ⋮ → 扩展 → Tampermonkey → 管理面板（Dashboard）→ 实用工具（Utilities），找到“从 URL 安装 / Import from URL”。粘贴下面这个地址，点“安装 / Install”，再确认安装。

助手只在本人的私有资料库 Releases 页面运行，借用 GitHub 原生上传控件；不需要新增云服务、网盘账号或授权码。此版本已做浏览器测试，仍需要在你的真实 GitHub 页面完成首次小批验证。

以后这样补传

  1. 先保存文件。在微信里打开文件，查看右上角菜单，选择保存到手机，或通过“用其他应用打开”保存到“文件 / 下载”。不同手机的名称可能不同。
  2. 用 Firefox 打开上传区。点下面的按钮，在 Firefox 登录自己的 GitHub。助手会尝试进入当前草稿；若停在列表页，点“书籍上传区”的编辑按钮。
  3. 确认助手出现。页面应显示“自动补传助手”和已识别附件数量。首次先选 2–3 个文件验证，不用特意挑缺失文件；如果显示无法识别或未连接，先不要整批上传，点“复制诊断信息”发给我。
  4. 重新全选。验证计数正常后，在附件框（Attach binaries）重新选择整批文件。助手按文件名和准确大小跳过成功附件，逐个补传剩余文件。支持 PDF、EPUB、PPT、PPTX 等附件，每个文件须小于 2 GiB。
  5. 看结果。上传失败会自动重试，三次重试后仍失败的可点“重试失败项”。同名但大小不同会提示冲突，不会覆盖。保持浏览器在前台；刷新或关闭后，需要重新选择手机文件，成功项会再核对并跳过。
  6. 保存草稿。全部成功后助手会尝试点击 Save draft。若提示需要自行保存，请点 Save draft；不需要点 Publish release，也不用改标签、标题或正文。
  7. 告诉我“已上传”。回到聊天发这句话，最好同时说一下分类。我会检查新文件，添加书目和前 10 页试读。需要讲义时，再告诉我书名、章节或学习目标。

上传遇到问题

  • 没有出现助手：确认正在使用 Firefox，Tampermonkey 与“Nicole 私有书架自动补传”脚本均已启用。GitHub 原生页面本身不会自动跳过同名文件。
  • 助手暂停：先看页面原因。不能可靠识别附件或失败占位项时，它会停止，避免误删；可把“复制诊断信息”的内容发给我。
  • 出现 Upload failed：该文件没有上传成功，继续等待或点击保存草稿都不会补传。先点失败项旁的 × 清除，再重新选择文件；可先用一个小文件验证。
  • 不用扩展时：仍可用原生页面手动上传，但需要自行避开已成功的文件，建议每批 5–10 份。同名且内容已修改的资料，请先改成不同名称上传，不要当作原文件补传。
  • 找不到文件：先确认微信中的文件已经下载完，再到手机“文件管理”的“最近 / 下载 / 文档”中查看。
  • 出现 404：先确认登录的是有权访问此私有仓库的 GitHub 账号。
  • 找不到附件框：尝试浏览器菜单里的“桌面版网站”，然后向下查找。
  • 网络中断：重新上传失败的文件。此入口不保证断点续传，上传期间尽量保持浏览器在前台。

完整原件留在私有仓库。公开书架只显示书名、分类和部分试读；上传后需要通知我处理，不会自动生成讲义。GitHub 页面可能仍显示 “Release / 发布” 等字样，请使用“保存草稿”。
