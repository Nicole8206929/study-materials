上传书籍

手机自带浏览器 · 重新全选，自动补齐。

首次保存“自动补传”书签后，就能在 GitHub 原有上传页补传。不装扩展，不启用新后台，完整文件仍留在私有资料库。

已通过浏览器模拟测试；OPPO／vivo 真机兼容性待验证。先看到“自动补传助手”，再选择文件。

1. 保存“自动补传”书签

正在准备书签…

  1. 在手机桌面打开 OPPO 或 vivo 自带的“浏览器”，打开本页。若当前在微信或聊天窗口，请通过菜单选择“在浏览器打开”。
  2. 点浏览器的菜单，选择“加入书签”或“收藏网址”，把名称改为自动补传。
  3. 点上面的“复制书签地址”，然后打开浏览器的“书签／收藏”列表，长按刚保存的“自动补传”，选择“编辑”。
  4. 把书签原来的网址全部删掉，粘贴刚复制的内容，保存。名称仍然是“自动补传”；网址以 javascript: 开头。这一步只需做一次。

2. 打开 GitHub 上传区

在同一个浏览器点下面的按钮，用有权访问私有资料库的 GitHub 账号登录。找到“书籍上传区”，点它旁边的编辑按钮，进入有 Assets / Attach binaries 附件框的页面。

打开私有上传区

找不到编辑按钮或附件框时，可以在浏览器菜单开启“桌面版网站”。不需要新建 Release，也不要点 Publish release。

3. 运行书签，重新全选

  1. 保持在 GitHub 上传区的编辑页，打开浏览器“书签／收藏”，点自动补传。如果没有运行，也可以点地址栏输入“自动补传”，从带书签图标的建议中点选，别按搜索。
  2. 附件框上方应出现自动补传助手和现有附件数量。首次先选 2–3 个文件验证，可以包含已上传文件；没有看到助手时，先不要整批选择。
  3. 确认正常后，在附件框重新全选这批文件。助手会在手机上计算校验值，跳过名称和内容都相同的成功附件，只补传缺失项；同名但内容不同会提示冲突，不会覆盖。
  4. 保持浏览器在前台。失败时会尝试重传，仍失败的点“重试失败项”。状态不明会暂停并保留原件；刷新或关闭页面后，需要重新运行书签，再选择手机文件。
  5. 全部完成后，助手会尝试保存草稿；若页面提示自行保存，点 Save draft。不要点 Publish release。
  6. 回到聊天告诉我“已上传”，我会核对实际文件。整理讲义和合并仍按你此前给出的要求处理。
保存或运行书签后没有变化？
  • 确认已经进入 GitHub 的上传区编辑页。书签只能在指定私有资料库中使用；在本说明页点它不会开始上传。
  • 编辑书签时检查：网址开头应为 javascript:，内容完整保留；不要放进书签的“名称”栏，也不要粘贴到搜索框。
  • GitHub 编辑页刷新后，需再次运行书签。正常上传需要微信里的文件先保存到手机的“下载／文档”。
  • 若浏览器拒绝保存这种网址，或运行后跳到搜索页，说明此版本可能不支持。下面的诊断按钮只复制浏览器信息；发给我后继续检查，不需要上传密码或验证码。
