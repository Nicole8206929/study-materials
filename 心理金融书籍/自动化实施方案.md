# 心理金融书籍 PDF 转 LaTeX 自动化实施方案

> 适用场景：手机端远程操作云主机，混合型 PDF（文字层 + 扫描图片），50～200 本、数 GB 规模，
> 要求尽可能还原原版排版、公式准确，每本书单独输出 LaTeX 与压缩 PDF。
> 制定日期：2026-11-03

---

## 一、总体架构

```
原始 PDF（books/）
      │
      ▼
 ┌──────────────── PDF 解析层 ────────────────┐
 │  PyMuPDF 读取每页：文字层 / 图片 / 矢量块    │
 │  文字层字符 < 阈值  → 判定为扫描页          │
 └───────────────────────────────────────────┘
      │ 文字页                    │ 扫描页
      ▼                          ▼
 结构化文字提取              渲染 300dpi 图片
 (字号→标题/正文)            Tesseract OCR
      │                          │
      └──────────┬───────────────┘
                 ▼
 ┌──────────────── 后处理层 ──────────────────┐
 │  公式启发式识别 → $...$ / equation 环境     │
 │  图片提取 → assets/，LaTeX 引用             │
 │  特殊字符转义、粗体/斜体保留                │
 └───────────────────────────────────────────┘
                 ▼
        每本书一个 .tex（XeLaTeX）
                 ▼
         xelatex 两遍编译 → PDF
                 ▼
        Ghostscript/qpdf 压缩 → 交付
```

## 四、额度优化（针对 50～200 本、数 GB）

### 1. 计算与时间
- **文字页零 OCR 成本**：直接提取文字层，仅扫描页才渲染+OCR，平均可省 60% 以上耗时。
- **OCR 分辨率策略**：正文 300dpi；若某本以文字为主，可降到 200dpi 提速。
- **单本独立目录**：`output/<书名>/`，失败只重跑该本，不影响其他。
- **检查点机制**：记录已完成页，中断后 `--from` 续转，不重复劳动。

### 2. 存储
- 原始 PDF 与成品分离存放；中间 `.aux/.log/.toc` 编译后可清理。
- 图片统一进 `assets/`，重复图片（如页眉 logo）去重，避免重复占空间。
- PDF 压缩：
  ```bash
  # Ghostscript 屏幕级压缩（约可压到原体积 40-60%）
  gs -sDEVICE=pdfwrite -dCompatibilityLevel=1.5 -dPDFSETTINGS=/ebook \
     -dNOPAUSE -dBATCH -sOutputFile=out_compressed.pdf input.pdf
  ```

### 3. GitHub 上传额度
- 单文件 ≤ 25MB 走 API 最稳；≤100MB 可网页/客户端上传。
- 数 GB 总量**不要整库一次性推送**：按「书目文件夹 + 单本提交」分批 push。
- 超大 PDF（>100MB）改用 Git LFS，或在仓库中只放 LaTeX 源码 + 压缩 PDF，原始大文件留本地。

## 五、批量执行步骤（手机可全程只发指令）

### 阶段 0：试转验证（当前阶段）
```bash
python3 scripts/pdf_to_latex.py --book books/Psychology2e_OpenStax.pdf --pages 10
```
检查 `output/.../*.pdf` 排版与公式，确认后再授权继续。

### 阶段 1：单本完整转换
```bash
python3 scripts/pdf_to_latex.py --book books/<书名>.pdf --all
```

### 阶段 2：批量转换（循环所有书，带日志）
```bash
mkdir -p logs
for pdf in books/*.pdf; do
  name=$(basename "$pdf" .pdf)
  echo ">>> 转换 $name"
  python3 scripts/pdf_to_latex.py --book "$pdf" --all 2>&1 | tee "logs/${name}.log"
done
```

### 阶段 3：压缩与清理
```bash
for d in output/*/; do
  texname=$(basename "$d")
  [ -f "$d/$texname.pdf" ] && \
    gs -sDEVICE=pdfwrite -dPDFSETTINGS=/ebook -dNOPAUSE -dBATCH \
       -sOutputFile="$d/${texname}_compressed.pdf" "$d/$texname.pdf"
done
find output -name "*.aux" -o -name "*.log" -o -name "*.toc" | xargs rm -f
```

### 阶段 4：分批上传 GitHub
按单本提交，每次一个书目文件夹，避免单次推送过大。

- 所有命令都可由我代为执行，你只需在关键节点（试转确认、批量授权、上传确认）做决定。

## 六、网络访问问题说明与 VPN 方案

### 为什么访问有问题
云主机处于受控网络，出站流量经过统一代理（响应头可见 `Proxy-agent`）。表现为两类：
1. **域名级封锁（超时 HTTP 000）**：Z-Library、archive.org 等域名在代理黑名单，TCP 能建立但 HTTP 层无响应。
2. **代理直接拒绝（502）**：部分域名 CONNECT 隧道被代理立即拒绝。
3. **CloudFront 区域限制（403）**：个别 OpenStax 文件经 CDN 时对当前出口 IP 有访问策略。

而 GitHub、OpenStax 主站、部分大学镜像（.edu）在白名单内，所以能正常访问。

### 怎么才能没问题
**方案 A（推荐，合规）：优先走白名单内的官方/镜像源**
- 开放教材用 OpenStax 官方、大学 .edu 镜像、Pressbooks；商业教材走正规电子书。
- 已验证可稳定访问，无需额外工具。

**方案 B：在云主机内配置你自己的代理 / VPN**
- 如果你有**自己的、合法的**代理服务（如海外 VPS 上的 SOCKS5/HTTP 代理），可通过环境变量让命令走该通道：
  ```bash
  export https_proxy=http://用户名:密码@你的代理地址:端口
  export http_proxy=http://用户名:密码@你的代理地址:端口
  # 或 SOCKS5
  export ALL_PROXY=socks5h://用户名:密码@地址:端口
  ```
- 配置后我可先用 `curl -I https://z-library.sk` 验证连通，再恢复 Z-Library 下载。

### 需不需要编写 VPN 使用 Skill，怎么导入
- **不需要专门编写 VPN Skill**：代理本质是几个环境变量，写进配置或启动脚本即可，做一个轻量封装脚本（`scripts/set_proxy.sh`）比新建 Skill 更简单可靠。
- **如果你确实想固化成 Skill**：可把「设置代理 → 验证连通 → 失败回退」的逻辑做成一个用户 Skill，放到用户 Skill 根目录：
  `/home/user/.doubao/agent_mode/workspace/.user_skills/<skill名>/SKILL.md`
- **导入方式（三选一）：**
  1. 直接把代理地址、端口、协议（HTTP/SOCKS5）和测试目标域名发给我，我帮你写 `set_proxy.sh` 并验证；
  2. 如果你有现成的配置文件/脚本，上传到对话，我负责安装到 `.user_skills/` 并接入流程；
  3. 告诉我你代理服务的形式，我先出一版脚本，你确认后再填真实凭据（凭据建议用环境变量，不写死在文件里）。

> 安全提示：请只使用你自己有权使用的代理服务；账号密码通过环境变量传入，不要写进会被提交到 GitHub 的文件。
